# Status and open items

Snapshot of where things stand (2026-10-03), so the next session can pick up. The repo moved from `zhanpetrov8-svg/digital-live-zoo` to `zhanpetrov/digital-live-zoo`; start new sessions with the new one. How the project is laid out: `CONTRIBUTING.md`.

## Working
- Site: single `index.html` on GitHub Pages (digitallivezoo.com), deployed straight from `main`.
- Analytics: PostHog (US cloud), project "Digital Live Zoo", dashboard "Digital Live Zoo". Custom events: `cam_on_stage` (with `activity` score), `cam_embed_blocked`, `wall_opened`, `wall_cam_added` / `wall_cam_removed`, `filter_changed`, `search`, `sound_toggled`, `tour_toggled`, `stage_fullscreen` (`on`, `mode`: `native` = browser full screen, `page` = fixed layer on phones like iPhone that can't put a page element full screen).
- Full screen: a button on the Main Stage player (also F key, double-click) puts the stage player alone on the screen; cam name, Sound / Touring / Next cam sit in a bar that hides after 3 s idle. Both stacked players go full screen together, so crossfades keep working.
- Smart tour: `tools/activity.py` scores each cam (CLIP "something to look at", movement, live viewers, viewer spikes) into `activity.json`; the Main Stage tour follows it, skips blank and off-air cams, and falls back to the 45-second tour without data (data counts for up to 3 hours).
- Learning from skips: every stage visit is logged as a PostHog `stage_segment` event (cam, habitat, daypart, activity level, viewers, seconds watched, how it ended: `skip` / `pick` / `tour` / `early` / `trouble` / `wall` / `hidden` / `leave` / `hold` / `resume` / `first`). A skip-hazard model sets how long the tour holds each cam and which cam comes next. Each browser learns its own viewer's skips (localStorage `zoo-segs`); `tools/attention.py` (daily, `attention.yml`) fits the shared model on all viewers into `attention.json`.
- Daily cam-list refresh: `.github/workflows/refresh.yml` (`tools/refresh.py`) since 2026-10-14. The old Claude routine on Zhan's Mac ("Digital Live Zoo daily refresh") is disabled: it had not updated the list since 2026-10-01 and used a stale artifact copy as its master list. Its prompt still names the old repo `zhanpetrov8-svg/digital-live-zoo` (GitHub redirects git, so it should keep working); switching it to `zhanpetrov/digital-live-zoo` needs Zhan's approval in a session linked to the Mac. Note it writes `catalog.json` whole, so keys other tools add to it (e.g. `mfk`) must also exist in the artifact's master list.
- Live visitor numbers (since 2026-10-23): header widget reads the Cloudflare Worker `zoo-live` at https://zoo-live.zhanpetrov8.workers.dev (Zhan's Cloudflare account, code in `tools/live-worker/`), which queries PostHog with the `POSTHOG_API_KEY` Worker secret and caches 30 s. Page polls once a minute; `zoo_here` heartbeat every 4 min.
- Weather at the cams (since 2026-10-24): `data/geo.json` holds hand-checked town-level coordinates per cam slug (plus `in` for indoor cams); cams only known to a country or state have none and show no weather. The `zoo-live` Worker refreshes MET Norway forecasts on a Cron Trigger (every 2 min, 24 places per run, each place every 15 to 30 min) into the Workers KV namespace bound as `WX`, and serves them at `/weather`. `assets/wx.js` renders them on the Main Stage, the cam cards and the cam pages (with sunrise/sunset computed in the browser). New cams need an entry in `data/geo.json` to get weather.
- Home page order (2026-10-24): logo + live visitor panel, Main Stage, intro text with cam counts and browse links, Most watched today (3 cards), Zoo map (MapLibre 4.7.1 from cdnjs + OpenFreeMap dark tiles, lazy-loaded; dots from `data/geo.json`, night side shaded, red pin follows the stage, click a dot to put it on stage, follows the filters).
- Field Station (`/field-station/`, public since 2026-10-24, linked from the home page): **100 open bilingual (`EN` / `RU`) global 360° wildlife expeditions** (`field-station/expeditions-data.js`) spanning all 8 world regions (Africa 16, Arctic 12, North America 16, Latin America & Reefs 14, Europe 15, Asia 13, Oceania 8, Antarctica 6), with research-calibrated Kids (`Junior`, Sobel/Piaget/Vygotsky/Shute/Chawla) and Adults (`Pro`, peer-reviewed biome ecology `sciRef` citations) editions, an interactive `Science & Child Development` modal, 100-Stamp Explorer Passport, region/daytime/search filters, and `fs_*` PostHog events. `field-station/vr360-player.js` (`DLZ360Player`) renders on-site WebGL 360° spherical media—both multi-audio 5m 51s sunrise-to-sunset HLS video (`streams/safari-v2/`) and 98 unique `2:1` equirectangular 360° habitat spheres (`panos/` + `scenes/quiver.jpg`) paired with 392 loudness-normalized Studio ElevenLabs `.m4a` voice guides (`audio/`, 400 voices total across EN/RU × Kids/Adults: Anna, George, Настя, Глеб)—synced with `ZooWx` solar phase (including polar day/night) & live MET Norway weather alongside 24/7 YouTube live cams.
- Stage captions (2026-10-25): `tools/activity.py` turns the picture model's best-matching animal prompt into a short caption ("Chicks in the nest"), only when it fits the cam's own animals (`data/cams.json`) or habitat; shown on the Main Stage as "Last look". 4th element in `activity.json`. Storyboard frames use a lower "nothing to see" cut (0.2) because they are smaller.
- Highlights only (2026-10-25): a Main Stage button tours just trending / action cams in the current view (falls back to the normal tour when none are hot); remembered per browser (`zoo-hl`), PostHog event `highlights_toggled`.
- Watchdog (2026-10-28): `.github/workflows/watchdog.yml` runs `tools/watchdog.py` hourly (started by the zoo-live Worker, cron every 3 h as backup). It checks the pages, `activity.json` (< 90 min old), `catalog.json` (< 36 h), the Worker (visitors, weather, chat) and whether any workflow failed twice in a row, and keeps one issue labelled `watchdog` open while something is wrong (GitHub e-mails the owner); it closes the issue when all is well. Workflows pinned to `ubuntu-24.04` and Node 24 actions (checkout v5, setup-python v6, cache v5).
- New cams weekly (2026-10-28): a Claude scheduled task in the cloud ("Zoo new cams weekly", Mondays 08:40 Pacific) picks up to 15 real animal cams from `data/candidates.json`, verifies them (oEmbed), names and places them, runs `tools/build_pages.py`, adds `data/geo.json` coordinates, moves non-animal candidates to `rejected`, and opens one pull request `new-cams-<date>` for Zhan to approve. It never merges or pushes to `main`.
- Cam pages (`/live`, `/animals`, `/places`, `/habitats`) are built by `tools/build_pages.py` via `pages.yml`.
- AdSense: verification meta tag, `ads.txt` and privacy page are live; the ad slot stays off until `window.ZOO_ADS.slot` is set.
